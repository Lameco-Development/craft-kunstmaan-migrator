# Plan 10-03: Page-Rooted Taxonomy Resolver

## Goal

When a migrated page references a taxonomy term, find or create the matching Craft taxonomy entry and link it even when no taxonomy state row existed before relation resolution. Default behavior is referenced-only; full unreferenced taxonomy import is explicit opt-in.

## Task 1: Extract shared taxonomy find/create resolver

Files:

- `src/load/TaxonomyMigrationService.php`
- `tests/integration/load/TaxonomyMigrationTest.php`

Action:

- Expose a resolver/upsert method from `TaxonomyMigrationService`.
- Accept taxonomy source identity and legacy ID.
- Check migration state first.
- Load the source row when state misses.
- Reuse existing mapping validation, SQL identifier whitelisting, entry save, localized fallback, and state recording.
- Return the Craft element ID in live mode.
- In dry-run, do not write Craft/state; report would-create/would-link counts and return a safe simulated/unresolved result.

Verify:

```bash
vendor/bin/phpunit tests/integration/load/TaxonomyMigrationTest.php --filter 'Lazy|Resolver|Locale|Fallback|Idempotent' --testdox
```

Done:

- Existing state rows are reused.
- Missing state row plus source row creates/updates taxonomy entry and records state in live mode.
- Missing locale values use default-language values and emit fallback visibility.
- Dry-run writes nothing and reports would-create/would-link.

## Task 2: Delegate taxonomy-backed relation misses to the resolver

Files:

- `src/fields/handlers/RelationHandler.php`
- `src/fields/ResolverContext.php`
- `tests/unit/fields/RelationHandlerTaxonomyResolverTest.php`

Action:

- Keep existing state-table lookup first.
- On non-empty state miss, call taxonomy resolver only when mapping/options identify the relation as taxonomy-backed.
- Do not invoke taxonomy fallback for non-taxonomy relations.
- Emit visible unresolved taxonomy relation reporting when resolution still fails.
- Keep empty source values empty without invoking the resolver.

Verify:

```bash
vendor/bin/phpunit tests/unit/fields/RelationHandlerTaxonomyResolverTest.php --testdox
```

Done:

- Non-empty taxonomy FK without prior state resolves to a Craft element ID in live mode.
- Non-taxonomy state miss remains unresolved and visible.
- Empty FK does not invoke resolver.

## Task 3: Add explicit full taxonomy import path

Files:

- `src/console/MigrateController.php`
- `src/models/Settings.php`
- `tests/unit/console/MigrateControllerTaxonomiesWiringTest.php`
- `tests/integration/load/TaxonomyMigrationTest.php`

Action:

- Default `migrate --live` behavior is page-rooted referenced-only taxonomy creation.
- Add `--include-unreferenced-taxonomies` and, if useful, `Settings::$includeUnreferencedTaxonomies = false`.
- Run `TaxonomyMigrationService::migrateAll(...)` only when flag/settings path is enabled, or through an explicit taxonomy sub-action.
- Report `taxonomyMode=referenced-only` or `taxonomyMode=full`.

Verify:

```bash
vendor/bin/phpunit tests/unit/console/MigrateControllerTaxonomiesWiringTest.php tests/integration/load/TaxonomyMigrationTest.php --testdox
```

Done:

- Default run does not import unreferenced taxonomy rows.
- Explicit flag/settings path imports unreferenced taxonomy rows.
- Taxonomy mode is visible in output/report.

## Acceptance Criteria

- Taxonomy-backed relation fields populate when source FK is non-empty.
- Referenced-only taxonomy mode is the default.
- Full taxonomy vocabulary import is opt-in.
- Taxonomy locale fallback and unresolved taxonomy relations are visible.
