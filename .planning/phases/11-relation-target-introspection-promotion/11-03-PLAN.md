# Plan 11-03: CraftEntryWalker

<objective>
Build `CraftEntryWalker`, a read-only candidate entry-rooted target graph walker that emits a normalized versioned graph of Craft entry types, fields, Matrix blocks, relation targets, asset volumes, and constraints.
</objective>

<tasks>
<task type="auto" tdd="true">
  <name>Implement entry-rooted Craft graph walker</name>
  <files>src/source/CraftEntryWalker.php, tests/unit/source/CraftEntryWalkerTest.php</files>
  <read_first>
    .planning/phases/11-relation-target-introspection-promotion/11-CONTEXT.md

    tests/unit/compile/CraftTargetIntrospectorTest.php
    tests/unit/console/AnalyzeControllerDualSchemaDumpTest.php
  </read_first>
  <action>
    Create `CraftEntryWalker` as a Yii `Component` in namespace `lameco\kunstmaanmigrator\source`. Add nullable public dependency `?CraftKnowledgeBase $craftKnowledgeBase = null`. Implement `public int $maxDepth = 4` and `public function walk(array $candidateEntryTypeHandles = [], ?int $maxDepth = null): array`. Return a normalized versioned graph with `graphVersion`, `roots`, `entryTypes`, `fields`, `matrixBlockTypes`, `matrixUsages`, `relationTargets`, `assetVolumes`, and `constraints`. Use Craft services through `CraftKnowledgeBase::dumpTargetSchema()` and existing catalog shapes; do not mutate Craft schema. Include candidate roots for provided handles such as `newsPage` and `homePage`, but keep production code generic. Implement a visited set keyed by Craft graph refs such as entry type refs, field refs, Matrix block refs, relation target refs, and asset volume refs. Use the visited set together with maxDepth to prevent repeated/nested Matrix or Entries references from duplicating indefinitely. Stable-sort registries by ID/handle.
  </action>
  <verify>
    vendor/bin/phpunit tests/unit/source/CraftEntryWalkerTest.php --filter 'Root|Version|Stable|ReadOnly|Entry' --testdox
  </verify>
