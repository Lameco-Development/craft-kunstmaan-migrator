## Finding

**Finding B — no existing marker exists in `kunstmaanmigrator_state` for
unresolved relations.**

Deferred references are handled entirely via in-memory token rewrites at
finalize time:

1. **`asset:N` deferred tokens** — emitted by `AssetHandler` and by
   `RelationHandler::resolveViaJoinTable` (asset-relation path,
   `src/fields/handlers/RelationHandler.php:218-220`) when a state lookup
   misses at transform time. Resolved at load time by
   `AtomicMigrationService::ingestAndResolveAssets` via `DeferredAssetToken`.
   No state-table row is written for the unresolved reference.

2. **`[NT<id>]` / `[M<id>]` CKEditor body tokens** — emitted by handlers when
   cross-entry / media references don't yet exist; resolved at finalize time
   by `CkeditorRewriterService` (FH-04 / FIN-01). No state-table row carries
   the deferred-token list — it lives only in the rewritten body content.

3. **`RelationHandler::resolveDirect` / `resolveViaJoinTranslation`** — when a
   state-table miss occurs for non-asset relations, the missed id is **dropped
   silently** (lines 110-115, 306-309). The handler intentionally does not
   write any `relation:deferred` state row.

The `kunstmaanmigrator_state` schema has no `kind` column (see
`src/migrations/Install.php` — 10 columns: id/source/sourceKey/targetType/
targetId/targetUid/siteId/meta/dateCreated/dateUpdated). The
`MigrationStateService` API has no method that emits a `relation:deferred`
sentinel row. No call site anywhere under `src/` writes a state row whose
`source` or `meta` payload could be queried as "this relation needs to be
re-resolved later."

## Recommendation

**Option B-3 — Defer REC-02 from Phase 4.1.**

Per Task 1's hard-scope restriction, Plan 07 MUST NOT introduce new
state-write code on `RelationHandler` or `AtomicMigrationService` (neither is
in this plan's `files_modified`, and adding the marker would expand scope by
extending the transform-stage handler surface). Implementing the marker
properly would also need a coherent design for which relation kinds get
deferred-row treatment vs which keep silent-drop semantics — that design
work belongs in a follow-on plan, not in 4.1's recovery surface.

Concrete consequences for Task 3:

- **`actionSyncAssets`** ships unconditionally (REC-01).
- **`actionSyncRelations`** is NOT added to `MigrateController`.
- **`tests/console/MigrateControllerSyncRelationsTest.php`** is NOT created.
- **`files_modified` reality** (recorded in the SUMMARY): the two
  sync-relations-scoped paths drop out.

Concrete consequences for Task 4:

- **REQUIREMENTS.md REC-02** stays `[ ]` (only 9 IDs flip to `[x]`).
- **`04.1-CONTEXT.md`** gains a `## Deferred Ideas` section with the deferral
  rationale captured here.
- **RECONCILIATION.md**'s requirement-closure table records REC-02 as
  "deferred to Phase 4.2 — no existing deferred-relation marker" and the
  Phase 4.1 traceability row in REQUIREMENTS.md omits REC-02.

## Why not B-1 (introduce a new marker convention this plan)

B-1 would require:
- New state-write path on `RelationHandler::resolveDirect` (and possibly
  `resolveViaJoinTranslation`) so silent-drop misses become deferred-row
  emits;
- New state-write path on `AtomicMigrationService::ingestAndResolveAssets`
  for the `asset:N` token-resolution miss path;
- A characterization-test corpus covering the miss-then-resolve loop end-to-end;
- A design decision on whether the marker carries the owning entry id
  (so `actionSyncRelations` can re-walk the right entries on re-resolve).

None of those are budgeted in this plan's `files_modified` list. The hard-scope
restriction in Task 1 explicitly forbids this expansion.

## Why not B-2 (alias REC-02 to `migrate/finalize`)

`migrate/finalize` (Phase 3 / Plan 06) walks every CKEditor field and resolves
`[NT<id>]` / `[M<id>]` tokens with the strict-unresolvable contract (FIN-02).
That path already exists. Adding `actionSyncRelations` as a thin alias would
be operator-confusing surface (two CLI verbs for one behaviour) and would not
satisfy REC-02's actual contract ("resolve any `relation:deferred` rows in
`kunstmaanmigrator_state`") — there are no such rows.
