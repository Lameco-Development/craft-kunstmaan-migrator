## Architectural Decisions Made

- **D-37 storage decision: meta JSON, not schema migration.** The terminal-state marker stores three keys (`terminalState='permanently_failed'`, `terminalReason`, `terminalAt`) inside the existing `meta` JSON column on `kunstmaanmigrator_state`, written via the existing `updateMeta()` array-merge path. PATTERNS recommendation (b). Zero schema risk; zero migration file under `src/migrations/`.
- **No `--retry-permanently-failed` knob.** Terminal state is FINAL by design (per the executor rule + REC-01 contract). Once a row is marked `permanently_failed`, no CLI flag re-enables retry — the operator's options are: (1) manually delete the state row to force a fresh attempt, or (2) accept the row as gone.
- **Recovery-command framing.** SYNC-ASSETS-{ts}.md report copy and inline help text both reinforce that `migrate/sync-assets` is a RECOVERY command, NOT a replacement for `migrate run`. The intended flow is: operator runs `migrate run`, sees skipped media in REPORT.md, then runs `migrate/sync-assets`.
- **REC-02 deferral over expansion.** Per the plan's hard-scope restriction (Option B-3 over B-1/B-2), the marker design work belongs in a coherent follow-on plan, not a slide-in.
