<decisions>
## Implementation Decisions

### .env reader

- **D-01:** New component `KunstmaanEnvReader` at `src/source/KunstmaanEnvReader.php` (mirrors location of other source-introspection components from Phase 02.1).
- **D-02:** Strict 2-key whitelist: `DATABASE_URL`, `DEFAULT_LOCALE`. Every other key is deliberately ignored — secrets in `.env` (Mollie / SAML / ElasticSearch / GTM / reCAPTCHA / etc.) never enter memory at all. The whitelist is hard-coded; adding keys requires a code change, not a config change.
- **D-03:** Read order matches Symfony convention: `KUNSTMAAN_SOURCE_PATH/.env.example` first, then `KUNSTMAAN_SOURCE_PATH/.env` (override). When both files exist, `.env` wins per-key. When `.env` is absent (rehearsal-against-checkout pattern), `.env.example` is the sole source.
- **D-04:** Parser: Symfony's `Dotenv` component (already a transitive dep — comes in via `symfony/console` chain). No regex-rolled parser. Key not in whitelist → ignored silently, not logged.
- **D-05:** Reader is a Yii Component registered in `Plugin::config()`; instantiated on first access via `Plugin::getInstance()->kunstmaanEnvReader`. Not in `Plugin::init()` sibling-DI graph (zero downstream consumer needs it at boot — every consumer is at command-invocation time).
- **D-06:** Failure modes: missing source path → reader returns blank values, no exception. Malformed `.env` → log + return blank. The reader never throws; it's defensive because operator setup state is variable.

### DATABASE_URL auto-fill (CFG-04)

- **D-07:** Hook point: `Settings::beforeValidate()` (Yii Model lifecycle). When `legacyDbServer` / `legacyDbDatabase` / `legacyDbUser` / `legacyDbPassword` / `legacyDbPort` are blank AND `kunstmaanEnvReader->databaseUrl` is non-empty, parse the DSN and fill the blank fields. Operator-supplied values always override.
- **D-08:** DSN parsing: PHP `parse_url()` with explicit `mysql://` / `mysql+pdo://` / `pdo:mysql:` scheme handling. Percent-decode each component (`urldecode()`) — Symfony DSNs URL-encode special chars in passwords. Query-string params (`?serverVersion=` etc.) ignored.
- **D-09:** Only `mysql` schemes are honored. PostgreSQL / SQLite / etc. → no auto-fill (Kunstmaan is MySQL-bound; this is a safety check, not a feature gap).
- **D-10:** Doctor 9th check (extending `DoctorController`): "Kunstmaan .env source" — reports file presence at source path + which whitelisted keys were found + (if `DATABASE_URL` present) whether the parsed host matches `Settings::legacyDbServer` (info only, never fail).

### LocalePreflight DEFAULT_LOCALE Rung 0 (LOC-03)

- **D-11:** Place the new rung BEFORE the existing three-rung ladder (`localeMap` / exact / prefix). Rung 0 doesn't replace the others; it adds an *advisory* doctor check that the operator-curated primary locale aligns with `.env`'s `DEFAULT_LOCALE`. The actual matching for migration purposes still goes through Rungs 1-3.
- **D-12:** Mismatch is a doctor WARN, never a hard FAIL. Justification: NL-default Kunstmaan migrating into an EN-primary Craft instance is a real and intentional pattern (content reflow); we don't second-guess the operator. WARN copy: "Kunstmaan default locale `<X>` but operator's `localeMap` lists `<Y>` first (Craft-primary). Reorder localeMap or confirm intent."
- **D-13:** When `KunstmaanEnvReader::$defaultLocale` is null/blank (env file missing or DEFAULT_LOCALE not set), the rung is silent — no doctor row at all. Don't WARN about a missing optional signal.

### CP slimming (CFG-05) + config-file overrides

- **D-14:** Two H2 groups in `_settings.twig`: **Connectivity** (legacyDbServer, legacyDbPort, legacyDbDatabase, legacyDbUser, legacyDbPassword, anthropicApiKey) and **Mapping** (kunstmaanSourcePath, mappingPath, localeMap). 9 fields total.
- **D-15:** 14 fields explicitly REMOVED from `_settings.twig` and documented in `config/kunstmaan-migrator.example.php`: legacyDbCharset, legacyDbTablePrefix, llmModel, llmTimeout, llmInterChunkDelay, defaultEntities, defaultLocales, defaultSince, defaultMaxPerEntity, dryRunDefault, verifyCountTolerance, verifyUrlDiffThreshold, seoTableName, redirectsTableName.
- **D-16:** No `Settings` class changes. The 14 properties remain on `Settings` with their current defaults; Craft's auto-loaded `config/kunstmaan-migrator.php` override mechanism is already wired via the standard plugin-settings flow. The phase's job is **template + documentation**, not Model code.
- **D-17:** `config/kunstmaan-migrator.example.php` ships at the repo root under `config/`. File header docblock explains: copy to `config/kunstmaan-migrator.php` in the consumer Craft site to override; multi-env via `*` / `.dev` / `.production` keys; values shown are the defaults.
- **D-18:** No tabs. At 9 fields across 2 H2 groups, plain markup wins. (Tabs would require switching from `settingsHtml()` to `getSettingsResponse()` for own-the-page control or HTML-only tab markup; not worth the cost.)
- **D-19:** Plan 04-05's RECONCILIATION.md grep `extends "_layouts/cp" = 1` is RETIRED — replace with fragment-shape check (assert NO `{% extends %}` in `_settings.twig`). Plan 04-05's `type: 'password' = 2` is RETIRED — replace with `forms.passwordField` shape check on the two secret fields. Both bug-codifying greps go via Plan 04.1-04.

### Editable-table dropdowns (CFG-06)

- **D-20:** Apply only to fields that survive the CFG-05 cut. After the cut, only `localeMap` is a CP editable-table; `defaultEntities` / `defaultLocales` move to config-file. Net: CFG-06 is a 2-column dropdown change on `localeMap` only.
- **D-21:** `localeMap` left column (legacy locale code): `type: 'select'` with options from `LocalePreflight::detect()` when DB reachable; free-text fallback when not. Detect failure path: catch DB exceptions in the settings render path, log via `Craft::warning`, fall back to free-text without breaking the page.
- **D-22:** `localeMap` right column (Craft site handle): `type: 'select'` with options from `Craft::$app->getSites()->getAllSites()`. No DB dependency — always available.
- **D-23:** Option-list construction lives in `Plugin::settingsHtml()` (or a thin helper called from it). Pre-compute both arrays once, pass into the Twig template via the existing `['settings' => ...]` payload.

### Adapter explicit-disable (ADP-04)

- **D-24:** `Settings::seoEnabled` + `Settings::retourEnabled` booleans, default `true`. Existing operators see no behavior change.
- **D-25:** Gate placement: at the top of `SeoMigrationService::migrate()` (and equivalent on Retour), BEFORE the `getPlugin()` presence check. Order: setting-disabled → SKIP; plugin-absent → SKIP; both present → run.
- **D-26:** CLI override flags `--no-seo` and `--no-retour` on `MigrateController`. They bypass the setting per-run without persisting. Implementation: thread through to the service via the existing `MigrationFilters`-style options blob (or a dedicated `AdapterFlags` value object — planner decides).
- **D-27:** REPORT.md "Skipped stages" section reports the *reason*: `seo` (explicitly disabled via Settings) vs. `seo` (plugin not installed) — two distinct row formats so operator can tell from the report whether a stage was opted out or unavailable.

### VerifyController $filters plumb-through (VER-04)

- **D-28:** Extend `CountGateService::run()` signature to accept a `?MigrationFilters $filters = null` parameter. When provided, scope the entry-count query (and optionally the asset / taxonomy counts) per the same predicates ExtractService uses (entities allow-list, locales subset, since cutoff). Default `null` preserves Phase 4 behavior.
- **D-29:** Same shape on `BaselineCounterService::capture()`. Captured baseline embeds the filter scope in the JSON header so a later `verify` run can refuse if filters don't match.
- **D-30:** When the captured baseline carries a filter scope and the current `verify` run was invoked with a different scope, doctor's 8th check (verify baseline presence) escalates from INFO to WARN with "filter-scope mismatch — baseline was captured with `<old>`, current run is `<new>`. Re-run capture-baseline or re-run verify with matching filters."

### DoctrineEntityParser attribute-only (SRC-20)

- **D-31:** Pre-flight grep across cqm / simac / enreach Doctrine entity files MUST verify zero `@ORM\` annotation hits before this lands. If any hit, the phase pauses and the operator is asked to confirm the project is OK to lose annotation support.
- **D-32:** Annotation-related branches are *removed*, not deprecated or feature-flagged. The class shrinks; tests for the annotation paths get removed too. No half-finished implementations.
- **D-33:** Comment headers documenting "this used to support `@ORM\` syntax — removed in 4.1 because all targeted projects are PHP 8+ attribute-only" are NOT added. The PR description carries that context; comments rot.

### Recovery commands (REC-01 + REC-02)

- **D-34:** New action methods on `MigrateController`: `actionSyncAssets()` and `actionSyncRelations()`. Routed as `kunstmaan-migrator/migrate/sync-assets` and `kunstmaan-migrator/migrate/sync-relations`.
- **D-35:** Both commands hit `kunstmaanmigrator_state` to find their work. `actionSyncAssets` queries rows with `source = 'media'` and a non-null skip-reason; `actionSyncRelations` queries rows with `kind = 'relation:deferred'` (or whatever the existing deferred-relation marker is — planner verifies).
- **D-36:** Idempotence model: each run computes the work-set fresh; rows already healed (source row has been successfully migrated since the marker was set) are silently skipped. No "have I run before" state — the work-set query is the source of truth.
- **D-37:** Terminal-state marker: a new column or status code on `kunstmaanmigrator_state` for "permanently failed" (e.g. `state = 'permanently_failed'`). Sync commands that hit a permanently-failed row report it in the run summary but don't retry. Planner decides exact column shape — schema migration may be needed.
- **D-38:** Same `MigrationFilters` contract as the main `migrate` command. `--entity=`, `--locale=`, `--since=` apply (e.g. operator can scope sync-assets to one entity's assets only).
- **D-39:** REPORT.md output: each command writes its own `SYNC-ASSETS-<timestamp>.md` / `SYNC-RELATIONS-<timestamp>.md` under `storage/migration/`. Format mirrors `REPORT.md`'s rehearsal summary section. Atomic write via `MappingFile::writeAtomic`.
- **D-40:** No queue. Synchronous, blocking command — same as `migrate`. Phase 4.2 (if pursued) would add the queue; out of scope here.

### REPORT.md always-emit (CFG-07)

- **D-41:** Strip the `if ($skippedStageLines !== []) { ... }` guard at `MigrateController.php:1107` and the `if ($report->assetRcaRows !== []) { ... }` guard at `:1154`. Both sections always emit.
- **D-42:** Empty-state copy: `_No skipped stages — all configured adapters were exercised._` and `_No asset RCA rows — no assets were migrated, or all migrated cleanly._`. Copy in Twig-style markdown italics for visual distinction from real content.
- **D-43:** No new section ordering, no new headings. Just remove the guards and add the placeholder copy. ~10 LOC change total.

### Claude's Discretion

- DSN parsing edge-case handling (Symfony's various DATABASE_URL formats — `mysql:` prefix, query params, multi-host) — planner can land whatever's pragmatic; D-08 is the floor.
- Whether `KunstmaanEnvReader` exposes raw DSN string vs pre-parsed components — planner can choose.
- Exact Twig template structure for the slimmed `_settings.twig` (D-14 sets the field list; D-18 sets no-tabs; details flexible).
- The `--no-seo` / `--no-retour` flag plumb-through (D-26) — through `MigrationFilters` extension vs dedicated `AdapterFlags` VO is a design call.
- Test layout for the recovery commands — characterization-style mirrors Phase 4 conventions; planner picks specific assertions.
- Handling of the terminal-state marker schema migration (D-37) — schema migration vs status-string-on-existing-column is implementation-grain.

</decisions>

<specifics>
## Specific Ideas

- **.env precedence pattern:** Symfony loads `.env` then `.env.local` then `.env.<APP_ENV>` then `.env.<APP_ENV>.local`. We deliberately read only `.env.example` + `.env` — `.local` files are project-developer-machine state, never the source-of-truth for migration. (Mentioned during the .env survey discussion.)
- **Reference projects validated:** cqm-website (NL, single-locale), simac-website (5+ locales, MULTI_LANGUAGE pattern), enreach-website (7 locales, including the `outbound` non-locale string in `REQUIRED_LOCALES` that confirmed why we don't read that key). Phase 5 rehearsal targets all three.
- **Anti-pattern to avoid:** Reading project-specific keys from .env (e.g. `CUSTOM_NAV_LANGUAGES`, `EXCLUDED_NAV_LANGUAGES`, `LIIP_IMAGINE_DATA_ROOT`). User feedback was explicit on this — only consistent-across-projects keys earn a place in the reader. The whitelist is intentionally short.
- **Reader is read-only:** Never re-writes `.env` / `.env.example`. Never includes them in REPORT.md or any other output artifact. Operator's secrets stay where the operator put them.
- **No CP runner, no Craft queue, no FeedMe-style remap utility.** These are deliberate exclusions — they reverse three locked Project Decisions and earn their own scope debate (Phase 4.2). Mentioning them here so a future planner doesn't slide them in.

</specifics>

## Existing Code Insights

### Reusable Assets
- `KunstmaanSourcePathResolver` (`src/source/KunstmaanSourcePathResolver.php`) — Phase 02.1 / Plan 01. The 4.1 env reader uses this to locate `.env.example` / `.env` (Component DI pattern; `??=` ladder; realpath validation). No new path logic needed.
- `LocalePreflight` (`src/locale/LocalePreflight.php`) — Phase 2 / Plan 01. LOC-03's Rung 0 is an advisory doctor check that wraps this; the existing detect/resolve/ensure surface stays. New code reads `KunstmaanEnvReader::$defaultLocale` and compares against `Settings::$localeMap[0]`.
- `EnvAttributeParserBehavior` (already wired in `Settings::behaviors()`) — Yii's standard env-var parser. Both `anthropicApiKey` and `legacyDbPassword` are already in the parser list. CFG-04's `DATABASE_URL` auto-fill complements this — env reader fills blanks, behavior parses `$VAR` references at read time. The two mechanisms compose cleanly.
- `MappingFile::writeAtomic` / `writeAtomicJson` (`src/mapping/MappingFile.php`) — Phase 2 / D-07. Used by every phase that writes operator-facing artifacts. REC-01 / REC-02 use it for SYNC-*.md output.
- `MigrationStateService` (`src/state/MigrationStateService.php`) — Phase 3 / Plan 03. REC-01 / REC-02 query and update via this service. The "permanently failed" terminal state (D-37) likely extends an existing status enum.
- `Plugin::settingsHtml()` (`src/Plugin.php:371`) — already returns rendered template HTML. CFG-06 dropdown options pre-compute here, pass into Twig via the existing `['settings' => ...]` payload.
- Symfony `Dotenv` component — already in the autoload tree via `symfony/console`. No new composer require needed for D-04.

### Patterns Already Established
- **Yii Component + sibling-DI in `Plugin::config()` + wiring in `Plugin::init()`** — every Phase 02.1 source-introspection class follows this. KunstmaanEnvReader follows the same pattern.
- **Doctor checks always return true; severity is in the prefix (`OK`/`INFO`/`WARN`/`FAIL`)** — Phase 4 / Plan 11 / D-69. Doctor 9th check follows the same shape.
- **CLI flags piped via `MigrationFilters`** — Phase 02.1 / D-09..D-13. ADP-04's `--no-seo` / `--no-retour` either extend MigrationFilters or use a dedicated AdapterFlags VO; the plumb-through site (`MigrateController` → service) is the same.
- **Atomic per-row writes for operator-facing files** — Phase 2 / D-07. REC-01 / REC-02 SYNC-*.md output uses the same primitive.
- **Test corpus growth via characterization tests at boundaries** — Phase 4 / Plan 12 pattern. 4.1 adds: KunstmaanEnvReader (DSN parsing edge cases + 2-key whitelist enforcement), DoctorController 9th check (4 outcome states), Settings::beforeValidate auto-fill (4 blank-vs-set permutations), CountGateService filter-scoped run, sync-assets / sync-relations idempotence + terminal-state.

### Risks
- **Symfony `Dotenv` API stability.** Pin the version range in composer if any direct API call is made. Symfony 6 → 7 had minor renames in the `Dotenv` namespace.
- **DATABASE_URL parser edge cases.** Multi-host DSNs (`mysql://host1,host2/db`), unix socket paths in the host position, percent-encoded passwords with `@` or `/` characters. Use `parse_url()` + careful percent-decode; document non-supported edge cases in CFG-04 implementation.
- **CP dropdown empty state.** When `LocalePreflight::detect()` raises (DB unreachable) or `KunstmaanSourceScanner` raises (path unset), the dropdown options array is empty. The fallback path MUST be free-text, not "no options selectable". Settings page must remain renderable in any operator setup state.
- **Annotation removal blast radius (SRC-20).** If any Kunstmaan-fork project we don't know about ships annotation-based entities, the phase silently breaks them. The pre-flight grep gate (D-31) catches the three known cases; we accept the risk for unknown forks (which would re-emerge in Phase 5 rehearsal anyway).
- **Sync-asset retry-loop hazard.** Without the terminal-state marker (D-37), sync-assets re-runs would forever re-attempt rows whose source files genuinely don't exist. The marker is load-bearing; D-37 must land in the same plan as REC-01.
- **CFG-04 silent override.** If an operator has manually set `legacyDbServer` to test-host but forgot to clear it before running against a different `.env`, the CFG-04 auto-fill silently does nothing (operator value wins per D-07). This is correct behavior but worth surfacing in the doctor 9th check output (D-10 already plans this).
