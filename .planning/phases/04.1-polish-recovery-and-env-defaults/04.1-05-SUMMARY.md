**1. [Rule 3 — Blocking] Updated MigrationFiltersTest characterization for new VO shape.**
- **Found during:** Task 1, after running `composer test`
- **Issue:** The Phase 02.1 / Plan 01 `MigrationFiltersTest::testClassHasExactlyThreePublicProperties` and `FilterFactoryTest::testFromCliMethodSignature` were bug-codifying greps that pinned the old 3-property / 3-arg contracts. Phase 4.1 / D-26 explicitly extends both with `noSeo` + `noRetour`.

Updated `testFromCliMethodSignature` to assert 5 args with the new names. Added two new positive cases (`testNoSeoAndNoRetourDefaultFalse`, `testNoSeoAndNoRetourPropertiesAreReadonly`) so the new invariants are locked.
- **Files modified:** tests/filter/MigrationFiltersTest.php, tests/filter/FilterFactoryTest.php
- **Commit:** e0449a4 (rolled into Task 1 commit)

**2. [Rule 2 — Critical Functionality] Skipped-stages aggregator extended for four new disable paths.**
- **Found during:** Task 3 planning, surfaced explicitly by the advisor (#1)
- **Issue:** The plan body said the four disable paths emit distinct copies but did not specify that the aggregator at `MigrateController::writeReport()` (the `foreach ($report->warnings as $w) { if (str_contains($w, ...)) ... }` loop) needs to recognize the four new substrings, otherwise D-27's "REPORT.md can tell them apart" invariant would be vacuous.
- **Fix:** Extended the aggregator from 3 patterns to 7. The four new patterns are: `SEO adapter disabled`, `Retour adapter disabled`, `skipped via --no-seo`, `skipped via --no-retour`. Locked by the new `testFourDistinctDisablePathSubstringsAreNotShared` test which asserts every pair of disable-path copies is distinct.
- **Files modified:** src/console/MigrateController.php (aggregator block)
- **Commit:** 18ab465 (rolled into Task 3 commit)

**3. [Rule 2 — Critical Functionality] Force `noSeo`/`noRetour` to `false` in their own sub-actions; refresh stale FILT-03 doctor comment.**
- **Found during:** post-execution polish, surfaced by the advisor
- **Issue (a):** The Task 3 `replace_all` over all eight `filterFactory->fromCli` call sites also rewrote the calls inside `actionSeo` and `actionRetour`. Result: `./craft kunstmaan-migrator/migrate-seo --no-seo --live` would build a `MigrationFilters` with `noSeo=true` — but `actionSeo` doesn't consult `$filters->noSeo` (only `actionIndex` does), so the flag would be silently inert. Worse, if a future contributor wires the bypass guard into `actionSeo`, the user-hostile semantic emerges (the sub-action that IS SEO honors `--no-seo`). The plan body explicitly warned against this: "For sub-actions where `--no-seo` makes no sense (e.g. `actionSeo` itself), pass `noSeo: false` explicitly to avoid surprise."
- **Issue (b):** `DoctorController` carried a stale FILT-03 comment claiming `--entities` / `--locales` / `--since` are no-ops on doctor. Phase 4.1 / D-30 (this plan, Task 4) made them load-bearing for the 8th check.
- **Fix (a):** `actionSeo` builds filters with `noSeo: false` (CLI flag forced off) and `noRetour: $this->noRetour` (passed through, inert here — actionSeo never calls the Retour service). Mirror in `actionRetour` (`noRetour: false`, `noSeo: $this->noSeo`). Inline comments document why.
- **Fix (b):** Refreshed the FILT-03 comment block to note D-30 made the flags load-bearing for `checkVerifyBaseline`.
- **Files modified:** src/console/MigrateController.php (actionSeo + actionRetour fromCli call sites), src/console/DoctorController.php (FILT-03 comment block)
- **Commit:** bceb66d
