    Create a real staged/batched `MigrationPipelineJob extends craft\queue\BaseJob` following the brownfield staged queue principle from `12-PATTERNS.md`, but without porting its overgrown pipeline. Public properties must be `int $runId`, `string $mode`, `array $filters = []`, `array $options = []`, `array $gateSnapshot = []`, `int $batchOffset = 0`, and `int $batchLimit = 50`. Only modes `dryRun` and `live` are allowed. In `execute($queue)`, re-check production first. For `live`, verify `gateSnapshot` contains no `blocked` or `unknown` gates before processing. Call `migrateWorkflow->run()` with `live`, `batchOffset`, and `batchLimit`, so each queue execution processes at most one batch. If the workflow returns `nextBatchOffset`, push a new `MigrationPipelineJob` with the same `runId`, `mode`, `filters`, `options`, `gateSnapshot`, `batchLimit`, and updated `batchOffset`; call `migrationRunService->appendQueueJobId($runId, $nextJobId)` after pushing. Only call `markSucceeded()` when no `nextBatchOffset` remains. Update progress after every batch.

<threat_model>
| Threat | Severity | Mitigation |
|---|---|---|
| Long-running migration runs inline in CP request. | High | Controllers enqueue these jobs; jobs call workflows outside web request. |
| Production safety is only checked before queueing. | Critical | Every job calls `assertNotProductionForJob()` inside `execute()`. |
| Queue payload serialization fails. | Medium | Public job properties are scalar or arrays only. |
</threat_model>
