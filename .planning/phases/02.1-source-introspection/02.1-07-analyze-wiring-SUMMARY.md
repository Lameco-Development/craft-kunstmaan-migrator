### D-42 11-step pipeline (was 8)

`actionIndex()` now orchestrates:

1. NeverProduction gate (FIRST — Phase 1 / D-20)
1.5. **KUNSTMAAN_SOURCE_PATH gate** (Phase 02.1 / D-31) — second gate; greenfield-fallback retired, ExitCode::CONFIG when unset/invalid
2. FilterFactory.fromCli + LocalePreflight.ensure (D-17 LOC-02 hard-fail with paste-ready locales block on FAIL)
3. **KunstmaanSourceScanner.scan** → `$sourceScan` (entity FQCN-keyed DoctrineEntityInfo + tables list + m2mJoins + bodyCols + mediaFks + drift)
4. **KunstmaanPageStructureScanner.scan** → `$pageStructure` (FQCN-keyed page records with contexts/allowedPagePartClasses)
4.5. **Page-part proposal emitter (locked here per advisor)** — walks `$pageStructure` × contexts × allowedPagePartClasses, calls `mappingFile->buildPagePartRow()` per tuple, accumulates into `$pagePartProposals`
5. `pageStructure.json` write (atomic JSON, sibling of schema-dump.json)
6. `SchemaDumper.dump($filters, $sourceScan['tables'])` → schema-dump.json (now consumes the scanner's table list)
7. **HeuristicProposer.autoMatch** with entity context wired in (`entityIndex` from sourceScan, `acceptedRows` from existing mapping.yaml)
8. **LlmClassifier.batchPropose** with KB markdown via v1-shaped adapter (B2 fix — replaces `'', ''` placeholders)
9. Build mapping rows + skip-existing merge (D-04 + D-34 kind-prefixed identity tuple). Page-part rows merge in alongside column rows.
10. MappingAuditor.audit (Plan 8 will extend with BlockAvailabilityValidator)
11. ReportBuilder.render → REPORT.md

### B2 fix: v1-shaped KB mapping adapter

`AnalyzeController::buildKbMappingAdapter(array $proposals)` (public static — testable without controller construction) reshapes v2's flat `proposals[]` into the nested shape `KnowledgeBase::renderPagesMarkdown` / `renderPagePartsMarkdown` actually read:

- `pageParts` → keyed by pagePart FQCN (matches v1 line 118)
- `sections` → keyed by `targetEntryType` (matches v1 line 399); column rows without a `targetEntryType` land in `_unmapped`
- `nodeClasses` → empty (reserved for Page entity FQCN annotations; v1 sources from a YAML key v2 doesn't ship — documented for future work)

Without this adapter, replacing the `'', ''` placeholders would have been **silently no-op for the mapping overlay**: KnowledgeBase reads nested keys, finds nothing, renders no annotations. The unit test (`AnalyzeControllerKbAdapterTest`) pins the adapter shape with 5 assertions.

### Heuristic 1.5 (D-44 entity-aware match)

Inserted between heuristic 1 (zero-fill drop) and heuristic 3 (exact-name). Resolution chain:

```
$tableName → DoctrineEntityInfo (via $entityIndex)
          → existing accepted column row for this table (via $acceptedRows)
          → resolved targetEntryType
          → match column name to entity property
          → match property name to Craft field handle on the resolved entry type
```

Higher confidence than the global exact-name match because it's scoped to the entity that owns the column. Emits `confidence='high'` → `statusForHeuristic` auto-promotes to `status=accepted` (D-02 ladder). When no accepted row exists for the entity yet, falls through to heuristics 3-9 unchanged.

`HeuristicProposer` gained two new public fields populated by AnalyzeController:

- `entityIndex: array<string, DoctrineEntityInfo>` — from `$sourceScan['entities']`
- `acceptedRows: list<array>` — `$existing['proposals']` filtered to `status=accepted` + `kind=column`

### SchemaDumper signature extension

`dump(MigrationFilters $filters, ?array $sourceTableList = null)`. When the caller supplies a discovered table list (Phase 02.1 / D-42 step 6), it's used directly. When `null`, the legacy `LIKE 'kuma\_%'` prefix scan still fires — preserved for unit-testability and for any future caller that bypasses the orchestrator.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Plan snippet for the KB adapter input was shape-wrong**

- **Found during:** Task 1 implementation
- **Issue:** The plan showed `array_merge($schemaDump['proposals'] ?? [], $heuristicProposals['accepted'] ?? [], $pagePartProposals)`. Neither `$schemaDump['proposals']` nor `$heuristicProposals['accepted']` exist — `SchemaDumper::dump()` returns `generatedAt/driver/tables/columns/locales` (no `proposals` key); `HeuristicProposer::autoMatch()` returns the matched list directly via positional destructuring (`[$heuristicProposals, $residual] = ...`), not a keyed array. Both `?? []` fallbacks would have silently fed the adapter empty input — the exact failure mode B2 was supposed to fix.
- **Fix:** Replaced with `array_merge($heuristicProposals, $pagePartProposals)`. Heuristic-matched rows lack an explicit `kind` discriminator (autoMatch doesn't stamp one) — the bucketer's `$kind = $row['kind'] ?? 'column'` default handles them correctly.
- **Files modified:** src/console/AnalyzeController.php
- **Commit:** 59858b5

**2. [Rule 3 - Blocker] Test required adapter extraction to a public static helper**

- **Found during:** Task 1 test authoring
- **Issue:** `tests/bootstrap.php` only loads `vendor/autoload.php` — no Craft / Yii base wiring. `AnalyzeController extends craft\console\Controller` and instantiating it requires `($id, $module, $config)` plus Yii lifecycle hooks. The plan acceptance criterion ("min 30 lines, asserts adapter buckets") could not be satisfied via inline orchestration testing.
- **Fix:** Extracted the adapter logic to `AnalyzeController::buildKbMappingAdapter(array $proposals): array` — `public static` so the test calls it directly with no controller construction. The plan explicitly authorized this ("if extraction simplifies testability, do it"). Test now lands 139 lines / 5 assertions covering pagePart bucketing, column bucketing, mixed input, empty-pagePartClass guard, and empty-input shape.
- **Files modified:** src/console/AnalyzeController.php · tests/console/AnalyzeControllerKbAdapterTest.php
- **Commit:** 59858b5

**3. [Rule 1 - Bug] Pre-existing duplicate-4 inline label in HeuristicProposer**

- **Found during:** Task 2 renumbering
- **Issue:** v1.x's `HeuristicProposer` carried two `// 4.` inline comment labels (one for `*_id → asset stem`, one for `TEXT/LONGTEXT → richtext`). Task 2's renumber pass (4-8 → 5-9) made the duplicate visible.
- **Fix:** Renumbered the inline labels to match the 10-heuristic class docblock: 1, 1.5, 3 (exact-name), 4 (`*_id`), 5 (TEXT/richtext), 6 (`*_image`/`*_photo`), 7 (`*_date`/`*_at`), 8 (`*_url`/`*_link`), 9 (`*_email`).
- **Files modified:** src/analyze/HeuristicProposer.php
