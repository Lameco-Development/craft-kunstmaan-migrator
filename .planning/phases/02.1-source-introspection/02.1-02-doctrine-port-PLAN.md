## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem (PHP source files under `{sourcePath}/src/Entity/`) → DoctrineEntityParser regex parser | operator-supplied filesystem content crosses into in-memory parsing |
| operator-supplied legacyDbServer / legacyDbDatabase → information_schema queries via DetailTableResolver | identifier-shaped operator input crosses SQL boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-02-01 | Tampering | DoctrineEntityParser regex | mitigate | Parser uses regex only — no code-execution primitive (no include/require of source files). PHP file contents are read with `file_get_contents()` and matched with `preg_match*` only. Worst case: malformed source produces a `Craft::warning` and the file is skipped (preserved verbatim from v1). |
| T-02.1-02-02 | Information Disclosure | DoctrineEntityParser RecursiveDirectoryIterator | accept | Iterator is rooted at the operator-supplied `$sourceCheckoutPath . '/src/Entity'`; `realpath` already validated by Plan 01 / D-33. No traversal beyond that root. |
| T-02.1-02-03 | Tampering | DetailTableResolver SQL | mitigate | All `information_schema.{TABLES,COLUMNS}` queries use bound parameters (`:db`, `:prefix`) — never string-concatenated identifiers. Pattern T-05.5-03-01 from v1 hardening preserved verbatim. Asserted by acceptance grep. |
| T-02.1-02-04 | Denial of Service | DoctrineEntityParser regex on large files | accept | v1 has shipped this against the CQM rehearsal corpus without DoS issues. Catastrophic backtracking risk on PHP source is bounded by file size (typical Kunstmaan project < 500 entity files, each < 1000 LOC). PHP's PCRE backtrack limit (`pcre.backtrack_limit`) provides a circuit breaker. |
</threat_model>
