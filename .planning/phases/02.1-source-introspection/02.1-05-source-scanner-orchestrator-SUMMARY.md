## Implementation Notes

### Task 1 — KunstmaanSourceScanner orchestrator

`src/source/KunstmaanSourceScanner.php` (432 LOC, `final class extends Component`).

**Public DI slots (6 typed nullable properties):**
- `?KunstmaanSourcePathResolver $pathResolver` — Plan 01 / D-33 source-path provider.
- `?DoctrineEntityParser $entityParser` — Plan 02 entity parser; warmed by feeding it the resolved source path before calling `getAll()`.
- `?DetailTableResolver $tableResolver` — Plan 02 resolver; held for symmetry / cache-warming so downstream consumers share the same parser cache.
- `?BodyScanColumnFinder $bodyFinder` — Plan 03; `scan()` returns `array<string, list<string>>`.
- `?MediaFkScanner $mediaScanner` — Plan 03; `scan()` returns `list<array{table, column}>`.
- `?LegacyDbService $legacyDb` — for the drift `information_schema.TABLES` query.

**`scan(): array` orchestration:**
1. Resolve source path; on null return `emptyResult()` (defensive — caller is gated by D-31 already).
2. Warm entity parser (`$entityParser->sourceCheckoutPath = $path`) and propagate the parser to DetailTableResolver if it's not yet wired.
3. Compute discovered tables: union of every entity's `tableName` + every ManyToMany `joinTableName`. Dedup + sort.
4. Compute `m2mJoins` via `collectM2mJoins()` (see below).
5. Call `$bodyFinder->scan()` for body-text columns.
6. Call `$mediaScanner->scan()` for kuma_media FK columns.
7. Compute drift via `detectDrift()` (see below).
8. Cache the full result and return.

**M2M end-to-end resolution (`collectM2mJoins`):** Walks every entity's relations; for each owning side with at least one ManyToMany, re-reads the entity file, extracts every `#[ORM\JoinTable(name: '...')]` via regex, and pairs them in file order with the ManyToMany relations from the parsed entity. Each emitted join carries `{ table, owning, inverse }` where `inverse` is the ManyToMany relation's `targetEntity` FQCN (the target/inverse class). The DoctrineRelationInfo VO already encodes targetEntity for both owning and inverse sides, so the M2M map is symmetrical from the consumer's perspective.

**Drift detection (`detectDrift`):** Queries `SELECT TABLE_NAME FROM information_schema.TABLES WHERE TABLE_SCHEMA = :db` (bound parameter — T-02.1-05-01 mitigation), then bidirectional diff:
- `dbHasButScanMissing`: DB tables NOT in scan, with KunstmaanCoreTables + any `kuma_*` prefix filtered out so only project content tables (lameco_websitebundle_*, etc.) surface.
- `scanHasButDbMissing`: scan tables NOT in DB (entity defined but never persisted — e.g. stale entity class).

If `legacyDb` is null or the query throws, drift degrades to empty arrays (Craft::warning logged) so the rest of `scan()` keeps working.
