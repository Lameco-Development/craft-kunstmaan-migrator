### KunstmaanSourcePathResolver (D-33)

New `final class KunstmaanSourcePathResolver extends Component` at `src/source/KunstmaanSourcePathResolver.php` (60 LOC). Single public method `resolve(): ?string`:

1. Reads `(string) (Plugin::getInstance()->getSettings()->kunstmaanSourcePath ?? '')`.
2. Returns `null` when empty.
3. Calls `realpath($settingsPath)` — returns `null` when `false` or not `is_dir()`.
4. Returns `null` when `!is_dir($real . '/src/Entity')`.
5. Returns the validated absolute realpath.

Caller contract: `null` means "fail closed" — no greenfield-fallback (D-31 supersedes the original roadmap's greenfield mode).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Plan/Codebase consistency] Used camelCase 'sourceStrict' instead of literal 'source-strict' in options() arrays**

- **Found during:** Task 2.
- **Plan said:** *"Add `'source-strict'` to the `options()` method's returned array (alongside 'audit-strict')."* The plan's verify command included `grep -c "'source-strict'"`.
- **Why this is wrong:** The codebase uses **camelCase property names** in `options()` everywhere — see existing `'noAi', 'autoAcceptHigh', 'auditStrict'` in `AnalyzeController::options()`. Yii's CLI layer dasherizes `auditStrict` → `--audit-strict` automatically; the literal string `'audit-strict'` does **not** appear in any existing controller. Adding `'source-strict'` (kebab-case) to `options()` would have either silently failed to register the flag or required adding a brand-new `optionAliases()` method that's absent everywhere else in the codebase.
- **Fix:** Followed codebase convention: `'sourceStrict'` in `options()`, `public bool $sourceStrict`. CLI surface is `--source-strict` (Yii's default conversion). Identical operator-facing behavior.
- **Files modified:** src/console/AnalyzeController.php, src/console/MapController.php.
- **Commit:** c87cee6.
- **Verify deviation:** `grep -c "'audit-strict'" src/console/AnalyzeController.php` returns 0 (proving no kebab-case precedent); `grep -c "'auditStrict'" src/console/AnalyzeController.php` returns 1 (proving camelCase is the convention).

**2. [Rule 1 — Plan acceptance grep specificity] Settings field declaration uses double-space alignment**

- **Found during:** Task 1 verification.
- **Plan acceptance criterion:** `grep -c "public ?string \$kunstmaanSourcePath" src/models/Settings.php` returns ≥ 1 (single space).
- **Reality:** Settings.php uses **double-space alignment** to align field declarations to the `=` column (existing pattern: `public ?string $anthropicApiKey      = null;`). My addition followed this pattern: `public ?string $kunstmaanSourcePath  = null;`. Single-space grep returns 0; extended-regex grep `grep -cE "public \?string +\\\$kunstmaanSourcePath"` returns 1.
- **Fix:** None needed — the alignment matches codebase style and the verify intent is satisfied. Documented for transparency.
