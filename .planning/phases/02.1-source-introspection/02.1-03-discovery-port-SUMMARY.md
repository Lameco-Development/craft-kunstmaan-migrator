## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] KnowledgeBase::loadAllColumns inline db()->createCommand chain replaced with $this->legacyDb->queryScalar()**
- **Found during:** Task 3 (writing the smoke test for KnowledgeBase)
- **Issue:** v1's `loadAllColumns()` inlines `$this->legacyDb->db()->createCommand('SELECT DATABASE()')->queryScalar()` to fetch the current MySQL database name. To exercise this in the smoke test would force the fixture to mock both `LegacyDbService` AND a `yii\db\Connection` stub (since `LegacyDbService::db()` returns `Connection`, and PHP enforces return types at runtime — duck-typed stubs don't satisfy the type). The Connection class transitively requires the full Yii application bootstrap, which contradicts Phase 1 / D-21 ("Craft is NOT half-bootstrapped from unit context").
- **Fix:** Replaced with `$this->legacyDb->queryScalar('SELECT DATABASE()')`. v2's `LegacyDbService::queryScalar(string $sql, array $params = [])` is the equivalent one-call surface — it wraps the same `createCommand($sql, $params)->queryScalar()` invocation internally. Semantics identical. Now the smoke test mocks through a single seam (LegacyDbService::queryScalar) instead of two (LegacyDbService::db + Connection::createCommand). Documented inline in KnowledgeBase.php with rationale and cross-reference to BodyScanColumnFinder + MediaFkScanner (which preserve the v1 db()->createCommand chain — those don't yet have smoke tests; the chain will be exercised at Phase 5 / TST-02 corpus characterization).
- **Files modified:** src/source/KnowledgeBase.php (loadAllColumns body + inline comment).
- **Verification:** php -l clean; KnowledgeBaseSmokeTest passes (41 tests / 88 assertions, 2 new tests both green).
- **Committed in:** 0635e9f (Task 3 commit).
