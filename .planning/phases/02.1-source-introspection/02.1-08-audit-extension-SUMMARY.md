# Phase 02.1 Plan 08: Audit-side Extensions Summary

**One-liner:** Ported v1's BlockAvailabilityValidator under `src/mapping/`, wired it as MappingAuditor's fourth finding kind (block-availability), added a sibling Drift section to MAPPING-AUDIT.md fed by KunstmaanSourceScanner's D-32 drift output, and extended CoverageAuditor to enforce page-part coverage (every declared page-part class with rows must have an accepted/dropped mapping.yaml row). Plugin component count 18 → 19.

## What Shipped

- **`src/mapping/BlockAvailabilityValidator.php` (123 LOC, NEW)** — verbatim port from `~/Sites/craft-kunstmaan-migrator/src/bridge/mapping/BlockAvailabilityValidator.php` with namespace flatten only (`bridge\mapping` → `mapping`). The `validate(array $mapping, array $matrixIndex, array $pagePartToNodeClasses = [])` signature, error message strings, optional cross-reference param, and `list<string>` return shape are all byte-for-byte preserved. D-21 invariant intact (legacyDbService line untouched).

### Task 2 — MappingAuditor block-availability finding kind + Drift section (commit b972242)

- **`src/mapping/MappingAuditor.php`** —
  - Added `public ?BlockAvailabilityValidator $blockAvailabilityValidator = null;` property (Yii component injection).
  - Extended `audit()` to call the validator after the existing FieldLayout walk when injected; translates each error string into a finding tuple with `kind: 'block-availability'`. Validator runs against a v1-shaped mapping built by the new private helper `buildV1ShapedMapping()` which walks v2's flat `proposals[]` filtering on `kind === 'pagePart'` AND `status ∈ {accepted, proposed}` (dropped rows are no-ops; needs-review is incomplete). matrixIndex passed empty pending Plan 09's KB port.
  - Extended `renderMarkdown()` to accept a second `array $driftFindings = []` param and emit a sibling `## Drift findings` section with two sub-buckets (`### DB has tables not in source scan`, `### Source scan declares tables missing from DB`). Empty buckets omitted; both empty → entire section omitted. D-32 single-file rule preserved.
- **`src/console/AnalyzeController.php` step 10** — forwards `sourceScan['drift']` as the second arg to `renderMarkdown()`. Adds a separate WARN/FAIL outcome for drift gated by `--source-strict` (existing `--audit-strict` continues to gate FieldLayout findings only). T-2-21 mitigation explicit: writeAtomic runs before any strict-mode `return ExitCode::UNSPECIFIED_ERROR`.

### Task 3 — CoverageAuditor page-part coverage enforcement (commit 1a4863e)

- **`src/mapping/CoverageAuditor.php`** —
  - `audit()` signature gains optional third param `array $pageStructure = []`. Caller (Phase 3 migrate --live + Phase 02.1 follow-up wiring in Plan 09) passes the page-structure scanner output.
  - New private helper `auditPagePartCoverage()` builds the set of all page-part classes declared in `pageStructure[*].contexts[*].allowedPagePartClasses` and the set of classes covered by mapping.yaml rows (`kind=pagePart, status ∈ {accepted, dropped}`). For every declared-but-uncovered class it emits a violation tuple `{kind: 'pagePartCoverage', pagePartClass, sourceTable, detail}`.
  - Column violations now carry `kind: 'column'` for symmetry (the existing `table, column, fillRate, rows` keys are unchanged so CoverageAuditorTest fixtures stay green).
  - `renderViolations()` splits the heterogeneous list by kind: column block grouped by table (Phase 2 / D-14 stderr shape preserved verbatim); page-part block under "FAIL Unmapped page-part classes: N" heading. Phase 3 `migrate --live` blocks on either kind being non-empty.
  - Fixed an incidental tightening — `covered[]` index now skips non-column rows so `table|column` keys can't collide with future kinds. Backwards-compatible because pre-D-34 mapping.yaml had no kind discriminator (defaults to 'column' when missing).

## Deviations from Plan

### Auto-fixed Issues

None — plan executed substantially as written. Two minor research-call shape decisions documented under Decisions in the frontmatter:

1. **Drift signature placement** — Plan suggested `audit($mappingProposals, $driftFindings = [])` storing drift on instance state or extending the findings tuple list. Chose to thread drift through `renderMarkdown($findings, $driftFindings = [])` instead. Cleanest separation of concerns: audit() returns FieldLayout-shaped findings (escalated by --audit-strict); drift is a separate concern (escalated by --source-strict). Same on-disk artifact (single MAPPING-AUDIT.md), same writeAtomic-before-return mitigation, fewer state cross-cuts.
2. **CoverageAuditor::audit() return type widened** — from `list<array{table,column,fillRate,rows}>` to `list<array<string, mixed>>` to accommodate the heterogeneous shape. Existing CoverageAuditorTest only asserts `table`, `column`, `fillRate` keys are present on column violations — those are still emitted exactly as before, plus the new `kind: 'column'` discriminator. Tests stay green (51/126 → 51/126, no new tests added in this plan).
