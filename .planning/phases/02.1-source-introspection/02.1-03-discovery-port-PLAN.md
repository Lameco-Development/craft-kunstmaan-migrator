## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator-supplied legacyDbServer / legacyDbDatabase → information_schema queries via BodyScan / MediaFk / KnowledgeBase | identifier-shaped operator input crosses SQL boundary |
| legacy DB row data → KnowledgeBase sample collection → LlmClassifier prompt → outbound Anthropic API call | legacy DB content (potentially PII) flows to a third-party API |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.1-03-01 | Tampering | BodyScanColumnFinder + MediaFkScanner SQL | mitigate | All information_schema queries use bound parameters (`:db`, `:prefix`). Identifiers are validated against `IDENT_RX` (in KnowledgeBase) before interpolation in dynamic queries. Pattern T-05.5-03-01 from v1 hardening preserved verbatim. |
| T-02.1-03-02 | Information Disclosure | KnowledgeBase sample collection | accept | Samples are truncated to `SAMPLE_MAX_LEN` (40 chars) and capped at `MAX_SAMPLES` (3 per column). The plugin is dev/staging only (NeverProductionTrait gates the analyze command — Phase 1 / D-20). PII risk acknowledged; operator's responsibility under the dev/staging-only deployment model. |
| T-02.1-03-03 | Denial of Service | TopologicalOrderer recursive depth | mitigate | `MAX_DEPTH_GUARD` constant (preserved verbatim from v1) caps recursion; cycle detection short-circuits to PHP_INT_MAX. The closure pattern is iterative with explicit `$visiting` set, not stack-blowing. |
| T-02.1-03-04 | Tampering | KnowledgeBase identifier interpolation | mitigate | The `IDENT_RX = '/^[A-Za-z0-9_]+$/'` const validates every dynamically-built table/column identifier before splicing into SQL queries. Failed validation → skip the column with a `Craft::warning`, do not interpolate. |
</threat_model>
