## Architectural Choices

### Reshape envelope vs. verbatim discipline

The plan's discipline was "port byte-for-byte; only deviate where v2's namespace flatness or dropped-class set forces it." The three deviations applied:

1. **Namespace flatten** (mechanical — D-41): `lameco\kunstmaanmigrator\kunstmaan\schema` → `lameco\kunstmaanmigrator\source` across all 6 files. PHPDoc FQCNs in the parser also flattened.
2. **`MigrationConfigError` → `\InvalidArgumentException`** (DetailTableResolver only): the v1 exception class doesn't exist in v2's surface; substituted with the standard library exception carrying v1's message format. Catches at consumer sites (Plan 5) become `catch (\InvalidArgumentException $e)`.
3. **Default `legacyTablePrefix`**: v1 shipped `'kuma_'` (vendor-scaffold default); v2 ships `'lameco_websitebundle_'` (CQM-rehearsal Lameco-bundle default per PLAN acceptance grep). The 7-table `$coreSkip` exclusion against `KunstmaanCoreTables::*` continues to filter vendor scaffolding regardless of which prefix the operator deploys.

Every other line — every regex, every cache shape, every method body, every `Craft::warning` call — is byte-for-byte from v1.

### KunstmaanCoreTables provenance

Ported from v1's `src/kunstmaan/db/KunstmaanCoreTables.php` (28 LOC, 7 consts), not its `src/kunstmaan/schema/` siblings. v1's docblock framed it as "introduced in Phase 5 Plan 02 during the pure-Core infra extraction (D-01 Step 1)" — preserved verbatim with one appended provenance line for v2 (`Ported verbatim under v2's flat source namespace per D-41`). v1 omits `declare(strict_types=1);` on this file; v2 mirrors the omission byte-for-byte.

### DoctrineEntityParser regex preservation

The 5 load-bearing PHP 8 attribute regexes (`/#\[ORM\\Table.../`, `/#\[ORM\\Column.../`, `/#\[ORM\\JoinColumn.../`, `/#\[ORM\\{relType}.../` × 4 relation kinds) and the legacy `@ORM\Column` docblock fallback regex are preserved character-for-character including the `(.{0,600}?)` / `(.{0,500}?)` lookahead bounds. Catastrophic-backtracking risk on PHP source is bounded by file size (typical Kunstmaan project < 500 entity files, each < 1000 LOC) and PHP's `pcre.backtrack_limit` circuit breaker (T-02.1-02-04 accepted in PLAN threat model).

### DetailTableResolver SQL safety

Both `information_schema.TABLES` queries (`scanMap()` + `allTables()`) use named PDO parameters (`':db' => $dbName`, `':prefix' => $this->legacyTablePrefix . '%'`); neither dbName nor prefix is ever string-concatenated into the SQL literal. T-05.5-03-01 mitigation preserved verbatim from v1's hardening pass. Asserted by acceptance grep.
